# Agent Rules — `app/src/modules/game/`

Scope: game engines (`*.engine.module.ts`) and the shared modules they compose. Global app rules and the validation procedure live in `app/CLAUDE.md`. Files under `app/src/modules/training/exercises/` share the `*.engine.module.ts` suffix but **not** this contract — see `app/src/modules/training/CLAUDE.md` (D264).

## Game engines

Every `*.engine.module.ts` here implements the `GameEngine` contract (`docs/architecture/04-Architecture-patterns.md` Pattern 18): constructed from a validated config snapshot bound to a `rulesetVersionKey`, owns its `EngineFacts` log, mints `clientKey`/`sequence`/`completedAt`/`participantRef`, rehydrates from persisted facts via `create(config, prior)`, and exposes a pure `wouldComplete(input)`.

- Every engine declares a static `stageOwnership` (`SHARED` | `PER_SEAT`) so `modules/game/seat-rota.module.ts` can derive the active seat from the fact log. `record()` takes no seat — it applies to the derived active seat, and the active seat is never stored. (2026-08-21)
- `undo()` is an exact inverse of `record()` over `facts()`, including any stage the record opened; undo depth is unbounded.
- `completedAt` is stamped when a visit resolves, never when it opens, and cleared when `undo()` reopens one.
- `state()` and `facts()` return derived copies — never a live field or a shared module constant. Anything a caller must change goes through a named method, not a write to a returned object.
- **Never store a value the fact log can derive** — no accumulated score, points, ratio or average fields.
- Compose log mechanics from `modules/game/turn-log.module.ts` and per-seat derivation from `modules/game/seat-state.module.ts` rather than re-declaring them. Copying a neighbouring engine's copy is what put `npx fallow` over its duplication gate once already (D232, 2026-08-23).
- A new engine's `rulesetVersionKey` and its server-side validator (`services/rulesets/registry.ts`) must land in the **same commit** — `scripts/check-game-engines.sh` runs pre-commit and rejects one without the other. (2026-08-14)
- `bash scripts/check-game-engines.sh` must pass. (2026-07-26)
- A single-stage, dart-input engine is a `DartGameSpec` bound to `dart-engine-shell.module.ts`, not a hand-written class; Doubles Training and Bob's 27 are the reference shape. One spec serves several ruleset versions via `rulesetVersionKeys` plus one `dartGameEngineFactory(spec, Engine, key)` per key (Singles Training, 2026-10-17). A timed spec reads `timerExpired` as `fold`'s third argument (set by the shell's `expireTimer()`); `isVisitOpen(turn, state, config)` sees the folded state, so a visit can close short (Around the Clock, 2026-10-17). A spec's optional `closedVisitTotal(opened, closed, participantRef, turn, config)` sets a closing visit's `totalScore` (Shanghai, 2026-10-17); `visitInput` lets a spec take a whole-visit total beside darts — the shell writes it as one closed dartless turn and `undo()` pops whole turns — with `coordinateCapture` resolving each dart from its coordinates (such a spec omits the optional `intent`, #1129, 2026-10-28) and leaving an open turn's total unwritten, and `complete(state, config, expiredAt)` replacing the default `isComplete()` (Ten Up One Down, 2026-10-27); `stageFor(state)` opens a stage per state (121's round per attempt) with turn `sequence` counted per stage and staged `undo()`, and `expiredAt` is the state at the latest `expireTimer()` (121, 2026-10-28). A shell migration of a shipped engine must prove itself with the differential oracle (`app/tests/modules/game/support/engine-oracle.ts`) before its golden snapshots replace the legacy copy. (2026-10-16, D462)
- Every `*.engine.module.ts` has a row in `scripts/engine-kernels.txt` (its rule-kernel family and status); `scripts/check-engine-kernels.sh` fails a new engine without one. See `docs/architecture/04-Architecture-patterns.md` Pattern 18 §Rule-kernel families. (2026-10-17, D467)
- A Track engine is a `TrackRules` mapper over `track-kernel.module.ts` (`applyTrackDart`, `foldTrackSeats`) and `track-policies.ts`, plus a projection from `TrackSeat` back to its own seat state so its exported reducer, fold and `state()` keep their shape. A policy lands with its first caller. (2026-10-17, D468)
- A Marks engine (Cricket, Tactics) is a `MarksRules` record (`initialSeat`, `hitOf(seat, opponent | null, observation)`, `valueOf`) turned into a game-shell spec by `marksGameSpec` in `marks-kernel.module.ts`; its fold is `foldMarks` (alone, or `foldMarksDuel` for two seats), its `wouldComplete` is `marksWouldComplete`, and `marks-close.module.ts` keeps the primitives. One spec serves V1 and V2; a factory for an unserved key throws. (2026-10-29, D506)
- A Checkout engine is a `CheckoutRules` record over `checkout-kernel.module.ts` (`applyCheckoutVisit`, `foldCheckoutVisits`) and `checkout-policies.ts`: the ruleset judges each visit (`judge` → `VisitVerdict`), books a closed attempt (`onAttemptClose`) — a `FAIL` verdict closes it at once, before the visit budget runs out — and names the next target (`nextTarget`, `null` ends the seat); a projection keeps its `state()` shape. A policy lands with its first caller. Random Checkout draws its next target with `seededDrawTarget` (2026-10-27); `foldCheckoutSeats` folds every seat of a game over its own turns, and `storedTotalJudge` and `ladderTarget` serve Ten Up One Down (2026-10-27); the kernel keeps a seat a policy marked `WON`, and `walkTotalJudge`, `winAtCap` and `untilWon` serve 121 (2026-10-28). (2026-10-27, D500)
- An Elimination engine is an `EliminationRules` record over `elimination-kernel.module.ts` (`applyEliminationDart`, `foldElimination`) and `elimination-policies.ts`: `onDart` returns every seat change one dart causes (lives clamp at 0, a seat at 0 is out, changes to an out seat are ignored); the kernel owns the rota (next seat still in) and `eliminationWinner`. It is a `SHARED`-stage `DartGameSpec` whose `isVisitOpen` closes a visit at its dart limit or the match end. Killer is the first. A game that decides a whole visit (Follow the Leader) adds the optional `onVisitClose` (a closed turn, with `initShared`'s `shared` slot, returns seat changes and the next `shared`) and `activeOverride` (rota stays on a seat owed a re-throw); a spec's `visitActions` (STOP closes an open darted turn, KEEP writes a closed dartless turn with `kept = true`) are shell inputs undone like a dart, and `isVisitOpen` must check `completedAt` so an action-closed turn is never reused. (2026-10-27, D501; 2026-10-29, D507)
- A Visit points engine folds through `visit-points-kernel.module.ts` (`foldVisitPoints`) with a `VisitPointsRules` record (`dartsPerVisit`, `points(total)`) and projects the seat onto its own state; a goal, bust, void or compare setting lands with its first caller. Score Training is one on the game shell; its spec sets `liveTotal`, so the shell keeps an open coordinate-captured visit's `totalScore` at its darts' sum (2026-10-28, D503). (2026-10-27, D502)
