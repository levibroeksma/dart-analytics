# Agent Rules — `app/src/modules/game/`

Scope: game engines (`*.engine.module.ts`) and the shared modules they compose. Global app rules and the validation procedure live in `app/CLAUDE.md`. Files under `app/src/modules/training/exercises/` share the `*.engine.module.ts` suffix but **not** this contract — see `app/src/modules/training/CLAUDE.md` (D264).

## Game engines

Every `*.engine.module.ts` here implements the `GameEngine` contract (`docs/architecture/04-Architecture-patterns.md` Pattern 18): constructed from a validated config snapshot bound to a `rulesetVersionKey`, owns its `EngineFacts` log, mints `clientKey`/`sequence`/`completedAt`/`participantRef`, rehydrates from persisted facts via `create(config, prior)`, and exposes a pure `wouldComplete(input)`.

- Every engine declares a static `stageOwnership` (`SHARED` | `PER_SEAT`) so `modules/game/seat-rota.module.ts` can derive the active seat from the fact log. `record()` takes no seat — it applies to the derived active seat, and the active seat is never stored. (2026-08-21)
- `undo()` is an exact inverse of `record()` over `facts()`, including any stage the record opened; undo depth is unbounded.
- `completedAt` is stamped when a visit resolves, never when it opens, and cleared when `undo()` reopens one.
- `state()` and `facts()` return derived copies — never a live field or a shared module constant. Anything a caller must change goes through a named method, not a write to a returned object.
- **Never store a value the fact log can derive** — no accumulated score, points, ratio or average fields.
- Compose log mechanics from `modules/game/turn-log.module.ts` and per-seat derivation from `modules/game/seat-state.module.ts` rather than re-declaring them. Copying a neighbouring engine's copy is what put `npx fallow` over its duplication gate once already (D232, 2026-08-23).
- A new engine's `rulesetVersionKey` and its server-side validator (`services/rulesets/registry.ts`) must land in the **same commit** — `scripts/check-game-engines.sh` runs pre-commit and rejects one without the other. (2026-08-14)
- `bash scripts/check-game-engines.sh` must pass. (2026-07-26)
- A single-stage, dart-input engine is a `DartGameSpec` bound to `dart-engine-shell.module.ts`, not a hand-written class; Doubles Training and Bob's 27 are the reference shape. One spec serves several ruleset versions via `rulesetVersionKeys` plus one `dartGameEngineFactory(spec, Engine, key)` per key (Singles Training, 2026-10-17). A timed spec reads `timerExpired` as `fold`'s third argument (set by the shell's `expireTimer()`); `isVisitOpen(turn, state)` sees the folded state, so a visit can close short (Around the Clock, 2026-10-17). A spec's optional `closedVisitTotal(opened, closed, participantRef)` sets a closing visit's `totalScore` (Shanghai, 2026-10-17). A shell migration of a shipped engine must prove itself with the differential oracle (`app/tests/modules/game/support/engine-oracle.ts`) before its golden snapshots replace the legacy copy. (2026-10-16, D462)
- Every `*.engine.module.ts` has a row in `scripts/engine-kernels.txt` (its rule-kernel family and status); `scripts/check-engine-kernels.sh` fails a new engine without one. See `docs/architecture/04-Architecture-patterns.md` Pattern 18 §Rule-kernel families. (2026-10-17, D467)
- A Track engine is a `TrackRules` mapper over `track-kernel.module.ts` (`applyTrackDart`, `foldTrackSeats`) and `track-policies.ts`, plus a projection from `TrackSeat` back to its own seat state so its exported reducer, fold and `state()` keep their shape. A policy lands with its first caller. (2026-10-17, D468)
- A marks engine (Cricket, Tactics) extends `MarksEngine` (`marks-engine.module.ts`) and supplies only `fold` and `fork`; its fold is `foldMarksSeats` over `foldMarksDuel`, and each ruleset key gets a `marksEngineFactory({ rulesetVersionKey, build })` in its own engine file; the engine class is generic in its key, so `build` must return an engine carrying the factory's key. (2026-10-24, D487)
- A Checkout engine is a `CheckoutRules` record over `checkout-kernel.module.ts` (`applyCheckoutVisit`, `foldCheckoutVisits`) and `checkout-policies.ts`: the ruleset judges each visit (`judge` → `VisitVerdict`), books a closed attempt (`onAttemptClose`) and names the next target (`nextTarget`, `null` ends the seat); a projection keeps its `state()` shape. A policy lands with its first caller. (2026-10-27, D500)
