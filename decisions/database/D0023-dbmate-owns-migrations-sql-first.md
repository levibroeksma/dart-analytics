# dbmate owns migrations (SQL-first)

## Context and Problem Statement
Keeps SQL chain canonical while getting types

## Decision Drivers
* The spec states that the SQL in `architecture/docs/database/` stays the sole schema source of truth, and that the Neon integration must not change the architecture's schema ownership model.

## Considered Options
* dbmate runs the SQL migrations; Drizzle only introspects for types (chosen).
* Drizzle-owned migrations via `drizzle-kit generate`. The spec lists this as a non-goal.

## Decision Outcome
Chosen option: "dbmate owns migrations (SQL-first); `drizzle-kit introspect` provides typed query layer only — Drizzle never generates schema", because Keeps SQL chain canonical while getting types.

### Consequences
* Good, because the SQL chain stays canonical while the app still gets typed queries.
* Neutral, because a new schema change is a new architecture migration, and `schema.ts` is regenerated by `drizzle-kit introspect` after each one.
