# Design: Issues #112, #113, #114

Status: canonical for this branch (historical once merged). 2026-08-15.

Three independent, small, owner-triaged UI fixes shipped together on one branch, per the 1.7.42 precedent (`docs/architecture/00-Context-Map.md`).

## #112 — Uppercase non-analytics game inputs

**Problem:** Recreational (non-`VISUAL_BOARD`) tap-input buttons show mixed-case labels ("Bull", "Bullseye"). All alphabetic game-input text should be uppercase.

**Scope:** `app/src/components/layout/games/SinglesRecreationalInput.astro` — the only tap-input component with literal mixed-case text ("Bull", "Bullseye"). `DoublesPathRecreationalInput.astro`'s "MIS" is already fully uppercase — no change needed. `ScoreInput.astro` (QUICK_SCORE keypad) is digits-only. `BoardInputPanel.astro` ("Bounce out") is `VISUAL_BOARD`/`ANALYTICS`-only, excluded by the issue's own title ("non-analytics").

**Change:** `Bull` → `BULL`, `Bullseye` → `BULLSEYE`. Plain text change, no logic touched.

## #113 — Singles Training session summary stats

**Problem:** `SinglesTrainingResults.astro` (the post-session modal) shows only "Total points." The live play screen already tracks miss/single/double/treble counts (`singles-training-play.data.ts`, shipped 1.7.37) but the summary modal doesn't surface them.

**Scope:**
- `app/src/lib/game/singles-training-play.data.ts` — widen the `resultsSnapshot` built in `uploadAndCompleteSession()`'s `buildResultsSnapshot` callback to add `misses`, `singles`, `doubles`, `trebles`, `hitPercentage`, computed from `this.$store.game.turns` (the fact log, still intact at completion time before any store reset) via the existing `countZoneKey` + the four `*_COUNT_ZONE_KEYS` sets already defined in that file. `hitPercentage` follows the existing `Bobs27Results`/`bobs27-play.data.ts` precedent: `Math.round((hits / darts) * 100) + '%'`, `"0%"` when no darts were thrown. Hits = singles + doubles + trebles (misses excluded).
- `app/src/lib/game/types.ts` — widen `SinglesTrainingPlayContext.resultsSnapshot`'s type to match.
- `app/src/components/layout/games/result-modals/SinglesTrainingResults.astro` — add four `StatRow`s (Darts missed, Singles hit, Doubles hit, Trebles hit) plus Hit percentage, alongside the existing Total points row.

No engine, schema, or API change — this is a display-layer read of facts already recorded.

## #114 — Setup pages back button

**Problem:** None of the 8 setup pages (`501`, `bobs27`, `121`, `singles-training`, `doubles-training`, `score-training`, `shanghai`, `around-the-clock`) has a way back to `/games` short of the browser back button.

**Scope:**
- `app/src/layouts/AppLayout.astro` — new optional `showBackButton?: boolean` prop (default `false`, so the layout's other consumers — games index, profile, statistics — are unaffected). When `true`, renders a header row above `<slot />`: a top-left icon-only `Button` (`variant="ghost" icon`, `ariaLabel="Back to games"`) that navigates via `@click="globalThis.location.href = '/games'"` — mirroring `GameLayout`'s existing Exit-button header shape and `play-lifecycle.ts`'s own `playBack` navigation. Icon: `chevron-down.svg` rotated 90° (`rotate-90` — clockwise, turning the down-chevron into a left-chevron), the same reuse-by-rotation trick `InfoSection.astro` already applies to the same icon (`-rotate-90` for its collapsed-state right chevron). No new icon asset.
- The 8 `app/src/pages/games/*/setup/index.astro` files — pass `showBackButton` to their `<AppLayout>` call.

No change to `GameLayout` (play pages) or any other `AppLayout` consumer.
