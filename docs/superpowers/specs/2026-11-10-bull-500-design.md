## 2. Why the kernel needs a hook

`applyVisitPointsTurn` scores a closed visit as `rules.points(total)`, where `total` is the sum of the darts' board scores. `voids(darts)` can zero a visit but cannot choose which darts count.

Bull 500 scores by dart order. A bull stores 25 or 50 but is worth 0. Darts before the first bull are worth 0. After it, only the 20 counts. No function of the dart sum can express that. So the kernel gets `pointsOf?(darts: readonly DartFact[]): number`; when present it replaces `points(total)`. `voids`, `goal`, bust and counters work as before. The kernel stays the home because everything else Bull 500 needs (visit count, running points, scoring visits, open-visit tracking, dart count) is already in `VisitPointsSeat`.

Builder's choice, recorded in the plan: make `points` optional with a type-level "exactly one of `points` / `pointsOf`", or keep `points` required and have Bull 500 pass an unused identity. Prefer the first if it does not touch the three existing callers.

Proof for the hook: Score Training, Score Threshold and Fives folds are byte-identical before and after (differential, as the Prisoner kernel change).

## 3. Rules the engine must express

From the rules file, V1 rows.

1. A visit is three darts, always all three. It starts **locked**.
2. Walking the darts in order: the first outer or inner bull unlocks and scores 0. After the unlock, a dart in the 20 scores its board score (single 20, double 40, treble 60). Any other dart, including a second bull, scores 0.
3. A visit's points are the sum. The total never goes down.
4. The game ends at the close of the visit whose running total is 500 or more. Overshoot is fine. The finishing visit is thrown in full.
5. Unlock does not carry to the next visit.
6. No visit limit.

Result: visits and darts to target, final total, best visit, useful unlock rate (visits whose first bull came on dart 1 or 2, over all visits).

### 3a. Calls from the design (Claude's calls)

- **Locked is derived** per visit from its darts, never stored.
- **`intent`**: the bull until the visit unlocks, then the 20 with no ring (rules file Capture). The spec's `intent` reads the open turn's darts.
- **`wouldComplete`**: true when the third dart of the open visit would take `seat.points + visit points` to 500 or more. Uses `pointsOf` on `[...open.darts, observation dart]`, as Fives does with `voids`.
- **Useful unlock rate** is computed in the results presenter from the turns' darts. The kernel's `scoringVisits` counts visits that booked points and does not equal it (a bull on dart 3 or no scoring dart on the 20 both book 0, but only the first is never useful).

## 5. Capture (Hard Invariants)

- **Capture / input mode:** `RECREATIONAL + DETAILED_DARTS` or `ANALYTICS + VISUAL_BOARD`.
- **Stage type:** one `EXERCISE_BLOCK` via `exerciseBlockStage()`.
- **`turns`/`darts`:** one `turns` row per visit, up to three `darts` rows. Intent is stored as null (§9, D544). Hit = number + zone. `score` = board score (a bull stores 25 or 50). `totalScore` = dart sum. Game points are never stored.
- **Derived, never stored:** locked state, each visit's points, running total, useful unlock rate, visits and darts to target, best visit.
- **Validator:** shared `.strict()` Zod schema in `lib/game/rulesets/types.ts`; server validator under `services/rulesets/bull-500/`; accepts only the two mode pairs above and refuses `QUICK_SCORE`.
- **Seeds:** `database/seeds/00NN_bull_500_game_engine_reference.sql` (next unused number, as `0058_fives_…`), game type, `BULL_500_V1`, one template preset, capability rows, tags from the rules file Tags table, plus a `database/verification/` check. No schema change (B7).

## 9. Builder-check outcomes (Claude's calls, for the owner to check)

- **Scoring oracle.** §3 and §6 restate the rules file's Visit section. The rules file wins on any difference; the plan re-reads it before writing the §6 tests.
- **Darts after 500.** The finishing visit is thrown in full: all three darts are entered and stored. Status flips at visit close. "Darts to target" is the total darts thrown (3 × visits), not the dart that crossed 500.
- **Bull intent (superseded 2026-11-10, D544).** The original call stored `intendedTargetNumber` 25, then 20, with no ring; that shape violates `chk_dart_target_consistency` (a number needs a ring) and no game could be saved. Bull 500 stores no intent, as Singles Training; the aim is derived from the dart order. A bull is number 25 (`BULL_TARGET_NUMBER`) in an `OUTER_BULL` or `INNER_BULL` zone; both unlock. Config keys are `target` and `live_number` (snake_case, not `liveNumber`). Hit zones `OUTER_BULL` and `INNER_BULL` are seeded in `0001_reference_data.sql`; the plan confirms the engine's existing bull handling needs no schema change (B7).
- **Wiring gate across the PR split.** Prisoner and Fives used the same split. If `check-game-wiring.sh` fails PR 1 without the UI, the two PRs merge into one.
- **B4 fallback.** If optional `points` touches an existing caller, keep `points` required and pass an identity from Bull 500.
- **Useful unlock rate.** Denominator is closed visits only; a live display may show the rate so far.
