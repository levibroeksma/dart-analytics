# Cricket V2 (CRICKET_V2) 1v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship two-seat Classic Cricket against a guest as ruleset version `CRICKET_V2`, with the 501 seat-switch animation and no new duplication. Solo stays `CRICKET_V1`.

**Architecture:**
- **Registration (Task 1):** key `CRICKET_V2`, the V1 validator reused, capability rows, seat cap 2, progress row, seed `0052`, `0007` triples.
- **Engine (Task 2):** `CricketEngine` takes a key parameter and serves both keys (the `TacticsEngine` pattern). The duel/solo fold, the engine class body (log, record, undo, `wouldComplete`, state, facts) and the per-key factory move to shared kernel code (`foldMarksSeats`, the `MarksEngine` base class, `marksEngineFactory`) that Tactics is refactored onto, so Cricket adds no copy of Tactics' engine code.
- **Shared play helpers (Task 3):** the row, accessor, title and winner helpers in `tactics-play.data.ts` move to one shared module (`marks-play.data.ts`) that Tactics and Cricket both call.
- **Play (Task 4):** setup picks the key from the guest list; Cricket and Tactics share one `MarksPlayScreen` over `SeatedPlayScreen` (the 501 shell); one shared marks replay presenter; results and replay learn two seats.
- **Proof (Task 5):** resume deck, replay-fold, derived-aims, stats-group tests.
- **Docs and gates (Task 6):** decision block, inventory, dupes comparison, visual check.

**Tech Stack:** TypeScript, Zod 3.25, Vitest, Astro + Alpine, PostgreSQL seeds, bash gates.

**Spec:** `docs/superpowers/specs/2026-10-24-cricket-v2-design.md`. Rules: `docs/game-rules/rulesets/cricket.md` (1v1 rows `V2`). ## Review Focus

1. Excess marks on the closing dart score only while the opponent has the number open; zero otherwise (Task 2).
2. The winning dart ends the game mid-visit: no further dart accepted, `completedAt` stamped, no hand-over after it (Task 2).
3. A closed-out seat that is behind keeps throwing and scores on numbers the opponent has open; either seat closing out level or ahead wins; no tie (Task 2).
4. Undo of a winning, a scoring and a dead-making dart restores the earlier state (Task 2).
5. A V1 solo log folds as before apart from `points: 0`; V2 solo folds as V1; Tactics behaviour is unchanged by the Task 3 extraction (Tasks 2, 3).
6. Guest opponent is selectable from setup and starts `CRICKET_V2`; no DartBot control; solo starts `CRICKET_V1` (Task 4).
7. Resume mid-game in either seat's turn; the resume deck keeps a V2 session on the Cricket card; V1 sessions replay unchanged (Tasks 4, 5).
8. Seven rows with two pip groups fit the 40% band at 390px and the switch animation fires on every hand-over (Task 6 visual check).

function marksPresenter(objectiveCount: number): ReplayPresenter {
  return {
    turn({ turn, after }) {
      const seat = seatIn<MarksDuelSeat>(after, turn.participantRef);
      const closed = seat.marks.filter((count) => count === 3).length;
      const cells = [
        valueCell("Marks", effectiveMarks(seat)),
        valueCell("Closed", `${closed}/${objectiveCount}`),
      ];
      return seatsOf<MarksDuelSeat>(after).length > 1
        ? [...cells, valueCell("Points", seat.points)]
        : cells;
    },
    session(steps) {
      const last = steps.at(-1);
      const duel = last !== undefined && seatsOf(last.after).length > 1;
      return finalLine<MarksDuelSeat>(
        steps,
        duel ? "Points" : "Darts",
        (seat) => (duel ? seat.points : seat.dartsThrown),
      );
    },
  };
}
