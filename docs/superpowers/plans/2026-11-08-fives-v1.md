# Fives V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `FIVES_V1`: a 2–4 seat race to exactly 51 fives points on the Visit points kernel, with void and bust.

**Architecture:** The Visit points kernel gains three optional rules, each landing with its first caller (visit-points spec V2): `voids` (a visit that scores nothing whatever its total), `goal` (an overshoot is a bust) and the counters they need. Fives is a `VisitPointsRules` record plus a `DartGameSpec` on the game shell, one `SHARED` leg like Killer. Two PRs: PR 1 is kernel, engine, validator, registries, seed; PR 2 is the screens.

**Tech Stack:** TypeScript, Zod, Astro, Alpine.js, Vitest, PostgreSQL seeds.

**Spec:** `docs/game-rules/rulesets/fives.md` (the rules input; no design doc — the calls below stand in for one and are the owner's to veto). Kernel precedent: `docs/superpowers/specs/2026-10-27-visit-points-kernel-design.md` (V2: a rule lands with its first caller).

Branches `feat/fives-engine` (Tasks 1–6), then `feat/fives-screens` (Tasks 7–9). Run app commands from `app/`; tests by path (`npx vitest run <path>`). Match the surrounding code: JSDoc on exports, no `//` comments in function bodies, exported types in `types.ts` files, TDD per `app/CLAUDE.md`.

## Calls made (not in the rules doc)

| # | Call | Why |
| --- | --- | --- |
| F1 | A visit is void when any of its darts has board `score` 0 | Every on-board dart scores 1 or more (outer bull 25); an off-board dart is a `MISS` zone dart with score 0. No new dart fact is needed. |
| F2 | The leg ends the moment a seat reaches 51; later seats do not throw | The rules doc's open question; the source says the first to reach 51 wins. Seat 1 has a first-throw edge, as in 501. |
| F3 | An off-board dart is a `MISS` zone dart with no landing coordinate under `VISUAL_BOARD` | The rules doc's third open question. A coordinate that lies outside the board is not stored as a position. |
| F4 | The kernel's `voids(darts)` and `goal` are optional and default to "never void, no goal" | Score Training and Score Threshold fold exactly as before; their goldens stay byte-identical. |
| F5 | A bust and a void are different outcomes and counted apart | The result lists voids and busts separately (rules doc §Result). A visit whose total is not divisible by 5 is neither: it is a plain zero. |
| F6 | A short visit (1–2 darts) is the open visit and scores nothing yet; a void is judged only on the closed visit | The kernel's existing open-visit rule; the engine never scores a partial. |
| F7 | `SEAT_CAPS.FIVES_V1 = 4` and `SEAT_FLOORS.FIVES_V1 = 2`; no DartBot | Rules doc: 2–4 seats, no solo. Killer's registry entries are the template. |
| F8 | QUICK_SCORE is not offered | A visit total cannot show an off-board dart (rules doc §Capture). |

## Global Constraints

- Ruleset key `FIVES_V1`; game type key `FIVES`; route slug `fives`; label `Fives`; Alpine data names `fivesSetup`, `fivesPlay`.
- Rules: visit = three darts, all thrown. Total divisible by 5 → fives points = total ÷ 5; otherwise 0. Any off-board dart → visit scores 0. Fives points that would take the running total above 51 → visit void for scoring (bust), total unchanged. Exactly 51 wins at once. Target 51, locked.
- Mode pairs: `RECREATIONAL`+`DETAILED_DARTS`, `ANALYTICS`+`VISUAL_BOARD`. Stats tags `["board"]`.
- Persistence (engine-only rule): capture `DETAILED_DARTS` / `VISUAL_BOARD`; one `SHARED` `LEG` stage for the game; one `turns` row per visit, one `darts` row per dart; `intendedTargetNumber` and `intendedZoneKey` both `null`; `score` = the dart's board score, never fives points. Totals, fives points, voids, busts and the winner are derived on read, never stored.
- 2–4 seats; seat order fixed at setup; seat 1 throws first.
- Seeds only; applied migrations `0001`–`0046` untouched.
- `FivesConfig` is `z.object({}).strict()`; preset configuration `{}` (target and rules are engine constants).
- Score Training's and Score Threshold's behaviour, exports and tests do not change.

## Review Focus

1. A visit whose darts total 45 but include one `MISS` scores 0, not 9; the same total on three board darts scores 9. (Task 2, 3.)
2. Exactly 51 on dart 3 of a visit wins at once; the next seat is never asked to throw; undoing the winning dart reopens the visit and the leg. (Task 3.)
3. At 50, a visit totalling 25 (5 points) busts: the total stays 50 and the bust counts; a visit totalling 5 (1 point) then wins at 51. (Task 3.)
4. A total not divisible by 5 scores 0 and counts as neither void nor bust. (Task 2.)
5. 180 scores 36; at 20 it busts (56), at 15 it wins (51). (Task 3.)
6. A visit of one or two darts is open: it scores nothing, shows its running sum, and undo across a visit boundary is exact. (Task 3.)
7. Folding from `prior` equals live recording over a seeded random run at 2, 3 and 4 seats. (Task 3.)
8. A kernel `VisitPointsRules` with no `voids` or `goal` folds exactly as before. (Task 2.)
