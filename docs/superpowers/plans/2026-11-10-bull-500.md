## Global Constraints

- Ruleset key `BULL_500_V1`; game type key `BULL_500`; route slug `bull-500`; code slug `bull-500`; label `Bull 500`; Alpine data names `bull500Setup`, `bull500Play`.
- Rules: visit = three darts, all thrown, starts locked. First outer or inner bull unlocks and scores 0. After the unlock a dart in the 20 scores its board score (S20 20, D20 40, T20 60); every other dart, including a second bull, scores 0. Unlock does not carry over. Game ends at the close of the visit whose running total is 500 or more; overshoot allowed; the finishing visit is thrown in full. No visit limit.
- Config `{ target: 500, liveNumber: 20 }`, strict, shown and locked. One seat. Kernel `VISIT_POINTS`, registered `KERNEL_BOUND` in `scripts/engine-kernels.txt`.
- Mode pairs: `RECREATIONAL`+`DETAILED_DARTS`, `ANALYTICS`+`VISUAL_BOARD`. No `QUICK_SCORE`. Stats tags `["board"]`.
- Persistence: one `EXERCISE_BLOCK` stage; one `turns` row per visit, up to three `darts` rows; `intendedTargetNumber` and `intendedZoneKey` both `null` (D546: a number without a ring violates `chk_dart_target_consistency`); `score` = board score (bull 25 or 50), never game points; `totalScore` = dart sum. Locked state, visit points, running total, unlock rate, visits and darts to target, best visit are derived on read, never stored.
- Seeds only; applied migrations are untouched. No DartBot seat, no career-stats page.
- Score Training, Score Threshold and Fives behaviour, exports and tests do not change.

## Calls made (beyond the spec)

| # | Call | Why |
| --- | --- | --- |
| P1 | A bull is `hitTargetNumber === 25` (`BULL_TARGET_NUMBER`); a live dart is `hitTargetNumber === 20` with a non-bull zone | Matches how stored darts identify a bull; an off-board `MISS` has `hitTargetNumber` null and scores 0. |
| P2 | `SEAT_CAPS`/`SEAT_FLOORS` get no entry | Spec B3 and the default `SEAT_CAPS ?? 1`. |
| P3 | Darts to target = `dartsThrown` from the kernel seat | Spec §9: 3 × visits. |
| P4 | Useful unlock rate is computed in the results presenter from the turns' darts, not in the kernel | Spec §3a. |

## Review Focus

1. Bull on dart 3 or no bull scores 0; a 25/50 bull never adds to the total. (Task 3.)
2. T20 before the bull scores 0: T20, bull, T20 = 60 not 120. (Task 3.)
3. Total passes 500 on dart 2: dart 3 is still accepted and stored; status flips to `COMPLETE` only when the visit closes; a dart after that is refused. (Task 4.)
4. Overshoot (e.g. 540) completes the game; no bust, total unchanged by the overshoot. (Task 4.)
5. Undo of the finishing dart reopens the visit and the game; rehydration from `prior` equals live recording over a seeded random run. (Task 4.)
6. Unlock does not carry: a bull on dart 3 of visit 1 leaves visit 2 locked. (Task 4.)
7. A second bull after the unlock scores 0 and does not re-unlock or double count. (Task 3.)
8. A kernel `VisitPointsRules` with no `pointsOf` folds exactly as before. (Task 2.)
