# Prisoner Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prisoner V1 playable end to end on the Elimination kernel: two seats, visual board only, capture and prison, budgeted visits, win by 20 or last seat holding darts.

**Architecture:** PR 1 adds two additive kernel hooks (per-dart shared state, ruleset-decided winner), a pure Prisoner policy and the `PRISONER_V1` engine, with a board-only validator and capability. PR 2 is app wiring on the shapes Follow the Leader proved (D509, D510, D511). `lives` is darts held (P8): prison is `−1`, capture `+1`, out at 0.

**Tech Stack:** Astro, Alpine.js, TypeScript, Zod, dbmate SQL (seeds only), Vitest.

**Spec:** `docs/superpowers/specs/2026-10-30-prisoner-design.md`. Rules: `docs/game-rules/rulesets/prisoner.md`. Exemplar: `docs/superpowers/plans/2026-10-29-follow-the-leader.md` (read it for the touch lists; this plan names only what differs).

## Global Constraints

- Keys: game type `PRISONER`, ruleset `PRISONER_V1`, route and code slug `prisoner`.
- Two seats exactly: one PLAYER plus one guest. No DartBot. Config `{ darts: 3 }`, `z.literal(3)`; `startingLives = darts`.
- `stageOwnership: "SHARED"`, one `EXERCISE_BLOCK` stage. Capture: `ANALYTICS + VISUAL_BOARD` **only**.
- A turn is closed only when `completedAt` is set. A skipped visit writes nothing.
- No migration. Seeds only (next free seed `0056`).
- Killer's and Follow the Leader's folds, snapshots and tests stay byte-identical (kernel changes additive).
- No `//` or `/* */` inside function bodies in `app/src`; JSDoc states the contract, not history. Exported types only in `types.ts`/`interfaces.ts`; import types from `@lib/types`.
- Wiring touch list lands in **one commit** per PR (`check-game-wiring.sh`; pre-commit takes ~8 minutes). Never `--no-verify`. Discovered work → GitHub issue, not fixed here.
- Decision id: `bash scripts/next-decision-id.sh` at write time (was D513 on 2026-10-31).

## Rulings made while planning (Claude's calls; recorded in the D-entry)

| Question | Call |
| --- | --- |
| Kernel hook shape | Two hooks, not one result field: `reduceDart(thrower, seats, shared, dart): VisitOutcome` (replaces `onDart` when present) and `decidedWinner(seats, shared): string \| null` (side key, beats last-seat-standing). `onDart` stays required; Prisoner passes `() => []`. |
| Win by 20 | `ext.target` becomes `21` on completing 20; `decidedWinner` returns that seat's side key. |
| Dart resolution | `resolveDart` (pure) judges one dart against the thrower's current `ext.target` and `shared.lodged`; zones: `OUTER_SINGLE` valid hit, `INNER_SINGLE` prison only when its number is the target, bulls prison, `MISS` counts toward `ext.missed`, everything else (incl. unbanded `SINGLE`) a plain miss. The validator, not the engine, refuses `SINGLE`. |
| Budget and skip | Resolved in `onVisitClose` as spec §3a: closing seat `sitting := missed`, `budget := lives − sitting`, `missed := 0`; walk later seats (closing seat last), clearing `sitting` and setting `budget := lives` on any not-out seat with budget 0, until one has budget > 0 → `shared.next`; `activeOverride` returns `shared.next`. |
| Spec correction | Spec §3a/§6 say the three-dart validator caps a turn at 3 darts. It has **no** dart-count cap (`three-dart.validator.ts`, `visual-board.validator.ts`). Prisoner's validator adds a ≤ 6 darts-per-turn cap and refuses unbanded `SINGLE`. It also overrides `validateConfig` to refuse the `RECREATIONAL + DETAILED_DARTS` pair the base validator accepts. Task 6 fixes the spec. |
| Replay labels | `Advance`, `Capture`, `Advance and capture`, `Prison`, `Miss` (bounce-out, off-board, double, treble and other plain misses all read `Miss`). |

## Review Focus

1. Inner single of the target, then outer single of it in one visit: held −1 then +1, target advances. Task 2.
2. Outer 20 at target 20 mid-visit: game ends, no further dart accepted. Tasks 1, 3.
3. Last held dart prisoned: seat out at once; a capture earlier in the visit keeps it in. Task 2.
4. Both seats fully sitting out: the walk skips and returns darts, no stall. Task 2.
5. Bull dart: held −1, nothing lodged, nothing capturable. Task 2.
6. Double, treble, off-target inner single, non-target outer single with no prisoner: no change, no sit-out. Task 2.
7. One valid hit on a number with several prisoners takes one; capture on a non-target number does not advance. Task 2.
8. A visit of 4–6 darts after captures. Tasks 2, 3.
9. Undo across a capture, a skip and the winning dart; rehydration equals live state at every dart. Task 3.
10. Keypad pair and unbanded `SINGLE` refused. Task 3.

### Task 2: Prisoner policy (pure)

**Files:**

**Interfaces:**
- Produces:
  ```ts
  type PrisonerExt = { target: number; missed: number; sitting: number; budget: number; captured: number; imprisoned: number };
  type PrisonerShared = { lodged: Readonly<Record<number, number>>; next: string | null };
  initialPrisonerExt(darts: number): PrisonerExt          // target 1, budget darts, rest 0
  resolveDart(thrower: EliminationSeat<PrisonerExt>, shared: PrisonerShared, dart: DartObservation): VisitOutcome<PrisonerExt, PrisonerShared>
  ```

- Consumes: `ClosedVisit`, `VisitOutcome`, `EliminationSeat`, `DartObservation`.

Rules, one decision per branch (spec §3): outer single of `n`: capture when `lodged[n] > 0` (`livesDelta +1`, `captured+1`, `lodged[n]−1`), advance when `n === ext.target` (`target+1`); inner single with `n === ext.target`: `livesDelta −1`, `imprisoned+1`, `lodged[n]+1`; outer or inner bull: `livesDelta −1`, `imprisoned+1`; `MISS`: `missed+1`; else no change. `resolveVisit` per the Budget-and-skip ruling above.
