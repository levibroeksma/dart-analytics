# Duplication Backlog — Phase 0 + Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Freeze the play/setup screens' public surface, then move the 14 game play factories onto a shared play-screen base so lifecycle code is written once.

**Architecture:** Alpine factories in `app/src/lib/game/*-play.data.ts` are object literals. Shared parts become small spreadable factories (the existing `boardInputData()` / `playAgainStarterData()` pattern) in one new file `play-screen.data.ts`; a game spreads the parts it has and keeps only its own members. Later object keys win, so a game overrides a shared member by declaring it after the spread. Proof of "nothing broke": a frozen surface snapshot per factory, plus the existing per-game behaviour tests passing unmodified.

**Tech Stack:** TypeScript, Alpine.js, Vitest, Astro.

**Spec:** `docs/superpowers/specs/2026-10-31-duplication-backlog-design.md`

**Scope of this plan:** spec Phase 0 and Phase 1 only, as three PRs (A, B, C). Phases 2–4 get their own plans after PR C lands, so they start from the real post-Phase-1 clone list.

## Global Constraints

- Owner reviews and merges every PR. Work stops after each PR is opened; the next PR's branch starts from `main` once the previous lands. At most one open PR beyond the one under review.
- No behaviour or UI change. Each factory's surface (key set + `typeof` per key) stays identical — no key added or removed.
- Existing tests under `app/tests/**` may change only imports or factory construction; no assertion edited, removed or weakened.
- No getters (`get x()`) in any shared part — object spread copies a getter's value once and breaks Alpine reactivity.
- No per-game boolean flags on a shared part. Variation = a separate part, a typed callback argument, or a later-declared override.
- `marks-play.data.ts` is a helper (`marksPlayAccessors`), not a factory; the 14 factories are: around-the-clock, baseball, bobs27, cricket, doubles-training, five-oh-one, follow-the-leader, killer, one-twenty-one, score-training, shanghai, singles-training, tactics, tuod.
- TDD per `app/CLAUDE.md`; no `//` comments inside function bodies; JSDoc above declarations, no decision history in comments.
- Each PR: `cd app && npm run validate:app`, `run-all-gates` skill, `bash scripts/check-dupes.sh` green; baseline lowered with `bash scripts/check-dupes.sh --update` only when it went down; `npm run format` before PR.
- Incidental findings → `discovered-work` issue (`capturing-discovered-work` skill); never fixed in pass.

## Review Focus

1. A shared method typed `async` where the original was sync (or vice versa) — Alpine ignores it, but a test doing `expect(ctx.back()).toBeUndefined()` would not. Surface test records `typeof` only; the behaviour tests are the guard — run each game's test file after its migration.
2. Key order: a game override declared *before* the spread is silently replaced by the shared version. Each migration task asserts the override is the one running (its existing test covers it; if none does, add one in that task).
3. `self` capture: `boardInputData` callbacks call `self.recordDart`; if the shared part's `init` does not set its own captured `self`, board taps throw on first dart. Task 4 tests a board tap after `init`.
4. Bot-aware vs plain undo: games without a bot (baseball, killer, tactics, follow-the-leader) must keep plain `playUndoVisit`. Task 4 tests both branches.
5. Timed games' `abandonAndExit` must still stop the countdown; untimed games must not throw when `timer` is absent. Task 4 tests both.
